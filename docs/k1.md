# K1：最小凭证注入与后续导入

2026-11-14。优先交付 Neowind 的 provider 环境注入，随后完成导入、审计和项目授权；不依赖同步或服务端扩展。本文是实施合同与第一切片计划，不表示 K1 已整体验收。

## CLI 与数据流

已有可用入口：人用 `keyref set` 从隐藏终端输入或受信 stdin 存值；agent 只提交 ref；`exec` 完成策略校验后直接启动子进程，向环境注入值，再脱敏 stdout/stderr。Neowind 的 `decision.rs` 已从 `api_key_env` 读取 key，只把 key 用于认证 header；配置文件不得保存 key。

```sh
keyref set neowind-provider --source local --allow-command neowind
keyref exec --source local --env JEV_API_KEY=neowind-provider -- neowind <command>
```

这里的 `JEV_API_KEY` 必须与 Neowind 配置的 `api_key_env` 一致；OpenAI/Google 的默认名分别是 `OPENAI_API_KEY` / `GEMINI_API_KEY`。如使用独立配置或状态目录，按需显式 `--pass XDG_CONFIG_HOME` / `--pass NEOWIND_STATE_DIR`，只传存在的变量。命令示例不含值，也不需要 `get --reveal`。Workcells 配置只持有 source/ref；本切片不采用 Workcells，不以协作工具接入作为联调前置条件。

后续 `keyref import-env --file <path>` 只解析 `export NAME=value` / `NAME=value`、空行、注释和引号；不执行 shell，不展开变量、命令替换、反引号或进程替换。整份输入先验证再写入；错误仅报告行号和错误码，不含原行。仅导入显式选择的变量，使用显式变量→ref 映射，避免大小写折叠、下划线转连字符造成碰撞；同样的输入不产生重复条目，无变化时不重写密文。只回报变量名、ref 与 created/replaced/unchanged，不回报值、值的 hash 或长度。映射、事务和幂等语义在导入切片落地前补回归。

## 威胁模型与边界

- 信任 Keyref、OS keyring 与指定的消费程序；同一用户权限下的恶意进程、调试器和任意 shell 不被本地库隔离。source/ref 前缀不是项目授权凭据。
- `allowCommands` 是名字白名单；`allowedHosts` 检查 argv 中 HTTP(S) URL 的真实 hostname。二者都不是 OS/网络沙箱，不能约束重定向、配置文件中的 endpoint 或任意脚本代码。Neowind 的 provider endpoint 在配置中，必须由集成方控制其配置与真实发送目的地。
- 输出脱敏覆盖已注入值及规定编码/trim 变体；子进程写文件、直接网络发送或变形输出不经过这道检查。Neowind 负责日志、回执、计划、状态文件与 provider 请求正文不落 key；验收必须扫描这些文件，不能仅检查终端。
- 默认 `get/list` 只读加密 meta；local `get --reveal` 仍缺控制终端确认，是 K1 的 P1 债务，不能用它接入 provider。配对 source 继续没有 reveal。
- 项目级最小权限后续要绑定受信调用入口和授权记录，在解密前拒绝未授权项目；只靠可伪造的 cwd、`--project` 或 source 名不满足“跨项目不能误用”。需要隔离对抗性同用户 agent 时使用进程权限隔离或 owner 审批，不能宣称 local 已提供这项保证。

## 第一切片：Neowind provider 契约

1. 复用现有 `exec --env`，固定消费者为 Neowind，给 ref 写 `--allow-command neowind`；不增加新的明文出口。
2. 用隔离临时 vault、合成 key、真实 Keyref 和真实 Neowind 产物对接本机 provider 夹具。夹具核对认证 header，只返回通过/失败，不回显 key；扫描输出、日志、计划、回执、状态文件。缺失 ref、锁定、错误消费者均须在启动前拒绝。
3. Keyref 交付命令/退出码与注入脱敏证据；Neowind 项目窗交付真实消费链和落盘扫描证据。既有 helper e2e 只能证明 Keyref 一侧，不能替代 Neowind 联调，更不能替代真实 App e2e。

第一切片无需总部追加决定；按既定边界推进。完整导入、本地审计和项目授权是后续切片；这些条件未满足前不宣称 K1 全部完成，也不读取真实 shell 凭证文件做试验。

Keyref 一侧的可重跑契约用例为 `go test -C cli -tags=e2e -run '^TestProviderEnvironmentContract$' -count=1 -v ./e2e`，核对三种 provider 环境变量、认证 header、两流脱敏、环境过滤及三个启动前拒绝码。它使用回环接收端和测试消费者；真实 Neowind 的证据单独记录，详见 [注入验收记录](k1-injection-evidence.md)。
